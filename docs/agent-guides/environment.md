## 环境变量

| 变量 | 描述 |
|----------|-------------|
| `PLANNOTATOR_REMOTE` | 设为 `1` / `true` 启用远程模式，`0` / `false` 启用本地模式，或不设置以自动检测 SSH。远程模式使用固定端口；浏览器打开行为取决于环境。远程模式绑定 `0.0.0.0` 并关闭以下功能：Ask this session（进程内和 pull bridge）、主机控制、agent 终端、open-in、Update now、实时应用标注、strict-gate 客户端租约。其余功能（批准/拒绝、反馈、agent 任务、`/api/git-add`、`/api/pr-action`、`/api/source/save`、`/api/save-notes`、SDK Ask AI）对任何能访问该 URL 的人保持可达。WSL2 不需要它（#1983）：本地模式绑定 `127.0.0.1`，WSL2 的 `localhostForwarding`（默认开启；镜像网络亦然）使 Windows 可通过 `http://localhost:<port>` 访问，且本地模式在未设置 `BROWSER` 和 `PLANNOTATOR_BROWSER` 且 WSL 互操作开启时已通过 `cmd.exe` 打开 Windows 浏览器（`packages/server/browser.ts` 中的 `isWSL`；Pi 的 `network.ts` 同理），因此指南告诉 WSL2 用户不要设置它。曾考虑"远程但绑定回环"的开关但未添加：其可达性与本地模式完全相同。远程就绪消息在 stderr 为 TTY 且通告主机被覆盖为非 localhost 时，还会渲染通告 URL 的终端二维码（localhost URL 的二维码扫描无意义），以便其他设备无需重新输入 URL 即可加入。**在代理或共享端口后面，使用远程模式。** 当 Host 为回环且无代理头时，本地会话将读取者视为本机（`isThisMachineReader`，#2291），并为此类读取者打开磁盘上任意位置的文档。默认设置的代理看起来像本地。例如，nginx 的 `proxy_pass http://127.0.0.1:<port>` 发送 `Host: 127.0.0.1` 且无 `X-Forwarded-For`。VS Code 开发隧道看起来也像本地。因此，本地会话前面的代理必须以远程模式运行或设置 `PLANNOTATOR_ALLOWED_HOSTS`，否则其后的每个读取者都能打开项目外的文档。GitHub Codespace（`CODESPACES=true`）会被检测并保留根目录。远程模式下，文件侧边栏仅提供会话根目录内的文件夹，且仅提供该机器上 Obsidian 列出的 vault（`referenceReadRefusal`，见 `server-and-storage.md` 中的"谁可以列出什么"）。根目录外添加的文件夹，以及 Obsidian 未列出的 vault，返回 `403`。 |
| `PLANNOTATOR_AGENT_TERMINAL_REMOTE` | 设为 `1` / `true` 以在 `PLANNOTATOR_REMOTE` 激活或会话通过 `--tailscale` 发布时启用标注模式的 agent 终端。两种情况默认关闭，因为会话可被网络对等方访问，且 PTY token 不是认证边界。 |
| `PLANNOTATOR_INBOX_PHONES` | Plannotator Inbox 整个手机界面的开关（见"Plannotator Inbox"下的"手机"）：配对、设备门 `/api/inbox/device/*`、tailnet 和 Wi-Fi 监听器、中继连接，以及设置 → 远程设备中的手机和配对手机。**默认：关闭**，直到 iPhone 应用和中继发布。关闭时，Inbox 不做任何与手机相关的事：每个配对、设备和可达性切换路由都返回未知路由 `404 { code: "not_found" }`，不打开任何 LAN 或门监听器，不为手机连接中继（已配对的云 agent 仍使用它：契约第 13 节"通过中继"），不生成证书，不运行 `openssl`、`tailscale` 或 Bonjour 进程，即使 `inbox.json`、`relay.json` 或 `devices.jsonl` 保存了开启时的运行状态（该状态保留供下次开启时使用）。唯一例外是已链接的机器（`docs/agent-guides/inbox-machines.md`）：当机器已链接或机器提议打开时，门会应答机器（机器的 token、机器提议的 `pair`，以及通过 tailnet 监听器或机器配对后的未知 token 返回 `401 device_token_invalid`），门监听器打开且 `tailscale serve` 在 8443 上发布它；最后一次取消链接后关闭。从未链接则不会发生任何这些。`1` / `true` / `on` 开启，`0` / `false` / `off` / `disabled` 关闭；空或无法识别视为未设置。也可通过 `~/.plannotator/config.json` `{ "inboxPhones": true }`；环境变量优先（`packages/shared/config.ts` 中的 `resolveInboxPhones`）。Inbox 启动时读取一次（`startInboxServer` 的 `phones` 选项覆盖它）；`GET /api/inbox/settings` 以 `phones` 携带它，窗口据此决定是否绘制该块。iPhone 应用的证明、中继证明、`tests/e2e/inbox-phones.spec.ts`、手机服务器测试（`createInboxWorld(..., { phones: true })`、`phones: true`）和 DAST 目标会设置它；`packages/server/inbox-phones-gate.test.ts` 证明两种状态。不在公开文档中。 |
| `PLANNOTATOR_INBOX_PREVIEW` | **临时，直到所有者发布 Shape 后移除。** 所有者在 0.28.49 和 0.28.50 中暂缓了 Code review 和 Shape；2026-11-17 Code review 的开关被放开（对所有人显示，除非开启否则关闭），Shape 仍暂缓。Plannotator Inbox 的设置 → 能力仅在 Shape 已在 config.json 中开启（`inboxShape`）或此变量恰好为 `1` 时显示 **Shape** 开关。为 `1` 时，其行在关闭时也显示，以便开启开关。其他任何值或未设置时，对关闭 Shape 的人不显示行。服务器决定它（`packages/server/inbox.ts` 中的 `heldSwitch`）。行隐藏时，`GET /api/inbox/settings` 省略 `shape`，`POST` 应答和窗口的 `event: capabilities` 亦然（除非该请求或事件是开关自身的保存）。设置不为缺失的键绘制行。已显示的开关仍可关闭。其行在下次加载时消失。功能本身不变：关闭时，agent 得不到其任何文本。它不再对 Code review 产生任何影响：不影响其行，也不影响其一次性提议（永不显示，`CODE_REVIEW_OFFER_SHOWN`）。每次请求时读取，不比较版本：删除 `heldSwitch` 即结束暂缓。无 config.json 键。不在公开文档中。测试：`packages/server/inbox-held-switches.test.ts` 和 `packages/inbox/settingsSections.test.tsx` 中的暂缓开关测试。 |
| `PLANNOTATOR_EXPERIMENTAL` | 实验性功能，每个**默认关闭**（所有者，批准 "inbox-decision-mode"）。逗号分隔的功能名列表：列出的名称开启该功能，带前导 `-` 的名称关闭它（`-decision-mode`）；名称去除空白并大小写不敏感比较，未知名称忽略，变量未命名的功能遵循 config.json `experimental`（`{ "experimental": { "decisionMode": true } }`），由 Inbox 的设置 → 能力 → 实验写入（`POST /api/inbox/settings` `{ experimental: { decision_mode } }`；变量决定时开关锁定，保存返回 `409 experimental_env_decides` 且不写入任何内容，如同 Over your tailnet 的锁定）。由 `packages/shared/config.ts` 中的 `resolveExperimental(config, name, env)` 解析，其小型 `EXPERIMENTAL_FEATURES` 表将每个名称映射到其配置键（更完整的标志注册表是包裹这些的独立工作）；`saveConfig` 逐键合并 `experimental`（仅当它是普通对象；手工编辑的非对象会被替换），因此切换一个功能保留其他功能。目前一个功能：`decision-mode`（见"Plannotator Inbox"下的"决策模式"）。每次请求时读取，因此更改立即生效。 |
| `PLANNOTATOR_RELAY_URL` | 新邮箱创建所在的 Inbox 中继（`packages/server/inbox-relay.ts`）。默认 `https://relay.plannotator.ai`。证明将其指向 `wrangler dev` 中继；测试指向关闭的回环端口。邮箱一旦创建，就停留在 `inbox/relay.json` 命名的 URL。 |
| `PLANNOTATOR_PAIRING` | 已配对云 agent 的配对字符串（`adr/implementation/inbox-mobile.md` 中的契约第 13 节），在其例程中设置。设置后，`plannotator inbox call` 作为该 agent 通过 agent 门，绝不通过 `/mcp`（`apps/hook/server/inbox-call-command.ts` 中的 `runPairedCall`）；`--session` 被拒绝。版本 2 字符串（中继应答时创建）命名中继，调用通过它密封进行（`packages/shared/inbox/agent-relay-client.ts`）；版本 1 字符串仅与 `PLANNOTATOR_PAIRING_DOOR` 配合使用。无需设置其他：中继地址来自字符串。 |
| `PLANNOTATOR_PAIRING_DOOR` | 与 `PLANNOTATOR_PAIRING` 配合：Inbox 在此计算机上的地址，`http://127.0.0.1:<port>`（localhost 和 `[::1]` 亦可，端口后无内容）。其他任何值被拒绝（`pairing_door_needed`）。设置后优先于中继。用于测试和本地替代例程。 |
| `PLANNOTATOR_PORT` | 要使用的固定端口。默认：本地随机，远程会话 `19432`。Plannotator Inbox 忽略它（以及 `PLANNOTATOR_REMOTE`）：它始终在其最后端口或随机端口上绑定 `127.0.0.1`；要从其他设备访问它，使用 `plannotator inbox --tailscale` / `PLANNOTATOR_INBOX_TAILSCALE`；见"Plannotator Inbox"。 |
| `PLANNOTATOR_LIVE_PORT` | 实时应用代理端口或包含范围，如 `19440-19447`（实时应用标注，见标注流程下的"实时应用标注"）。使用第一个可用端口并始终绑定 `127.0.0.1`。对于 SSH 转发，设置 `PLANNOTATOR_REMOTE=0`，用 `PLANNOTATOR_PORT` 固定编辑器端口（本地模式为随机），并转发编辑器和代理端口，两侧保持相同端口号。范围会跳过已在使用或此用户无权绑定的端口（`EACCES`，非 root 时低于 1024 的端口）；当无一可用时会话启动失败并输出一行（`packages/shared/live-proxy-port.ts` 中的 `LiveProxyPortError` / `LiveProxyPortInUseError`，已 vendored 到 Pi：CLI 退出 1，或在严格标注门下退出 2，标注服务器先关闭其编辑器监听器）。无效值在 stderr 警告并使用随机端口。两种传输均读取（`packages/server/live-proxy.ts`、`packages/shared/live-proxy-node.ts`）；从不遵循 `PLANNOTATOR_PORT` 或 `PLANNOTATOR_REMOTE`。默认：随机。 |
| `PLANNOTATOR_PUBLIC_URL` | 为反向代理（Cloudflare Tunnel、Caddy、code-server）后的远程会话通告的完整 HTTP(S) 源，例如 `https://plannotator.example.com`；按原样打印和打开，不附加运行时端口。与 `PLANNOTATOR_PORT` 范围一起使用时仅适用于第一个端口；后续端口回退到 `PLANNOTATOR_URL_HOST` 或 `localhost`。随机端口（`PLANNOTATOR_PORT=0`）亦然，代理无法定位它。仅源：凭据、路径、查询、片段或非 HTTP(S) 方案在 stderr 警告一次并以相同方式回退。仅显示且仅远程，如同 `PLANNOTATOR_URL_HOST`：它从不改变绑定接口或同机 agent API URL，本地会话忽略它并在每进程警告一次。因此同机隧道（cloudflared、code-server）需要 `PLANNOTATOR_REMOTE=1`，它绑定所有接口并关闭"Ask this session"。远程模式下实时应用标注不可用，因此无法通过公共 URL 工作；使用 `--static`。远程模式下其主机名也在 Host 允许列表中，因此转发浏览器 Host 的代理无需 `PLANNOTATOR_ALLOWED_HOSTS`。由 `resolvePublicUrl`（`packages/shared/config.ts`）和 `resolveAdvertisedSessionUrl`（`packages/shared/advertised-url.ts`，已 vendored 到 Pi）解析。也可通过 `~/.plannotator/config.json`（`{ "publicUrl": "https://plannotator.example.com" }`）设置；环境变量优先，空值抑制配置键。在其前端端口上优先于 `PLANNOTATOR_URL_HOST`，包括 `plannotator.localhost`（远程会话无论如何忽略该名称）。默认：未设置。 |
