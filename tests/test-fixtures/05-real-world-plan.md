# 实施计划

## 概述

本计划为 Plannotator 渲染器增加对 Markdown 硬换行和列表续行的支持。

## 变更

### 1. 解析器更新

- **合并续行**到前一个列表项：当该行有缩进且中间没有空行分隔时执行合并。这处理了 Claude 将长列表内容折行到多行的常见情况。
- **新增 `lastLineWasBlank` 跟踪**，防止在空行后合并——按 CommonMark 规范，空行应开始新段落
- **保留现有行为**，其他所有块类型不受影响——标题、代码围栏、表格、引用块和水平分割线均不变

### 2. InlineMarkdown 更新

- 新增硬换行模式匹配：
  - 两个尾随空格后跟换行（`  \n`）——标准 Markdown
  - 反斜杠后跟换行（`\\\n`）——替代语法
- 更新回退字符扫描器，在 `\n` 和 `\\` 处停止，使硬换行模式有机会匹配
- 软换行（无尾随空格的普通 `\n`）仍通过常规 HTML 空白处理折叠为空格

### 3. 同步到 Diff 视图

- `PlanCleanDiffView` 有独立的 `InlineMarkdown` 实现，需添加相同的硬换行模式以保持一致

### 4. 测试覆盖率

- 新增 6 个解析器测试，覆盖：
  - 简单续行合并
  - 多行续行
  - 无缩进行（不应合并）
  - 空行分隔（不应合并）
  - 嵌套列表项不被续行逻辑吞并
  - 列表项后的块级元素不被吞并

## 修改的文件

| 文件 | 变更 |
|------|------|
| `packages/ui/utils/parser.ts` | 续行合并逻辑 |
| `packages/ui/components/Viewer.tsx` | InlineMarkdown 中的硬换行 |
| `packages/ui/components/plan-diff/PlanCleanDiffView.tsx` | 硬换行同步 |
| `packages/ui/utils/parser.test.ts` | 新增测试套件 |

## 风险评估

两项变更均为增量式且范围狭窄。标注系统使用基于文本的匹配（`findTextInDOM`）作为主要恢复机制，因此对块结构变化具有韧性。

> 注意：本计划本身就是一个很好的测试用例——它包含带续行的列表项、行内代码、表格、引用块和混合内容。
