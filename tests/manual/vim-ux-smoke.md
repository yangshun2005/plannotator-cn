# Vim 控件用户体验冒烟测试

本冒烟测试从评审者的实际使用角度评估 Vim 控件。它不是逐键实现清单：每个旅程都从真实的用户意图出发，一并验证焦点、移动、选择、标注、恢复和反馈。

在两条渲染路径上运行完整矩阵：

- plan 或 annotate 应用中的 Markdown。
- 通过沙箱化 HTML 查看器加载的原始 HTML，使用 `tests/test-fixtures/vim-ux-smoke.html`。
- Select 和 Pinpoint 两种输入方式。
- Vim HUD 的 Key 面板分别可见和隐藏。

## 启动

构建并运行真实的 plan 应用：

```bash
bun run build:hook
bun run dev:hook -- --host 127.0.0.1
```

通过真实的 annotate 服务器运行原始 HTML 测试夹具：

```bash
PLANNOTATOR_REMOTE=1 \
PLANNOTATOR_PORT=3019 \
PLANNOTATOR_AI=disabled \
PLANNOTATOR_SHARE=disabled \
bun apps/hook/server/index.ts annotate tests/test-fixtures/vim-ux-smoke.html
```

启用 **Settings → Vim → Vim controls**。当场景需要可见的目标反馈时，启用 **Vim HUD**。

## 旅程 1：无需寻找焦点即可开始评审

**用户意图：** 打开文档后立即开始移动。

1. 打开一个启用了 Vim 控件的中性文档。
2. 不点击文档，直接按 `j`、`k`、`gg` 和 `G`。
3. 聚焦某个应用控件，然后按 `Escape`。
4. 再次按 `j`。

预期：

- 文档就绪后自动获得焦点。
- 第一个目标是真实的语义块，绝不是整个文档。
- `j` 和 `k` 每次移动一个可见块。
- `gg` 和 `G` 跳到第一个和最后一个块。
- `Escape` 从应用中性界面返回文档。
- 不出现文档大小的浏览器焦点环。
- 打开的对话框、编辑器、选择器或编辑区优先拥有 `Escape`；该层关闭后焦点才返回。

## 旅程 2：按文档结构浏览

**用户意图：** 以段落粒度快速浏览长计划，然后检查某个结构化区域。

1. 用 `j` 和 `k` 在标题、段落、列表、代码块和表格之间移动。
2. 停在包含粗体、代码或链接的段落上，按 `l`。
3. 用 `j` 和 `k` 在行内同级元素间移动；按 `h` 返回。
4. 停在表格上，按 `l` 进入行，在行间移动，按 `l` 进入单元格，在单元格间移动，用 `h` 逐层退出。

预期：

- 块移动遵循渲染后的阅读顺序。
- 代码块是一个块；在用户进入文本前，其行和 token 不是独立的块目标。
- 细化遵循有意义的层级：`table → row → cell → text` 和 `paragraph → inline target → text`。
- `j` 和 `k` 在当前层级的同级元素间移动。
- `h` 上升一个语义层级，且不会意外改变位置。
- Select 和 Pinpoint 解析出相同的可见目标。

## 旅程 3：高效导航到精确文本

**用户意图：** 到达某个变量、值或句子片段，而不必逐字符步进。

1. 用 `l` 细化进入文本。
2. 在散文和源代码中使用 `w`、`b` 和 `e`。
3. 用 `0` 和 `$` 跳到行边界。
4. 用 `j` 和 `k` 按视觉行移动。
5. 用 `{` 和 `}` 在文本块间跳转。
6. 用 `h` 和 `l` 做最后的字符调整。

预期：

- 单词移动跳过整个单词/token，而不是前进一个字符。
- 行和段落移动让长距离导航明显更快。
- 源代码标识符、数值、标点和散文都可到达。
- 光标位于文本边缘；不会切分高亮的 token。
- 视口仅在需要时滚动以保持活动目标可见，且按键之间不抖动。

## 旅程 4：精确选择要讨论的内容

**用户意图：** 选择短语、单个代码值或多个完整块。

1. 从文本按 `v`，用文本移动扩展，选中一个散文短语。
2. 对代码标识符和数值（如 `3` 或 `1_500`）重复。
3. 按 `o` 交换固定端和移动端，细化另一端。
4. 在段落或代码块上按 `V`。
5. 用 `j` 扩展整块选择，用 `k` 收缩。
6. 再次按 `V` 返回当前语义块。

预期：

- 可视选择精确匹配可见字符，包括代码。
- 高亮几何从选中字形开始和结束。
- `o` 改变哪一端移动，但不改变选中的文本。
- 整块 Visual 只选择预期的块范围——不包含无关的列表项、编号或相邻块。
- HUD 准星跟随活动范围，并正确标注精确文本与整块。

## 旅程 5：标注而不丢失目标

**用户意图：** 对当前目标评论、红线、打标签或标记，然后继续评审。

从语义块和精确 Visual 范围分别执行每个操作：

- `c`：打开评论。
- `d`：创建红线。
- `t`：打开快速标签，用数字快捷键选择一个。
- `m` 或 `Space`：打开共享标注工具栏。
- `Enter`：应用当前选中的工具栏模式。

预期：

- 每个操作使用与指针选择相同的工具栏、编辑器、高亮器、标注模型和侧边栏条目。
- 编辑器接收所有键入字符——包括 `j`、`k` 和 `gg`；它拥有焦点时文档导航冻结。
- `Command+Enter` 保存评论。
- `Escape` 只取消打开的操作，恢复文档焦点，并恢复精确的源范围。
- 保存后也恢复精确范围，即使高亮标记改变了 DOM。
- 红线立即应用，并返回一致的文本或块状态。
- 快速在代码块上导航不会仅因此打开评论编辑器。

## 旅程 6：复制并继续

**用户意图：** 复制精确短语或完整块，然后继续评审。

1. 做 Visual 选择并按 `y`。
2. 粘贴到原生文本字段。
3. 用 `V` 选择完整块，按 `y`，再次粘贴。

预期：

- 剪贴板文本与可见选择完全一致。
- Visual 复制后折叠为文本光标；整块复制后返回块导航。
- 文档焦点保持活动，下一个 Vim 键立即生效。
- 原始 HTML 通过经过验证的父级桥接复制，不向沙箱添加 `allow-same-origin` 或剪贴板权限。

## 旅程 7：从 HUD 学习而不牺牲空间

**用户意图：** 使用目标准星，同时选择显示多少按键指引。

1. 启用 Vim HUD，在块、行内、文本、Visual 和操作状态间导航。
2. 用关闭控件隐藏右下角 Key 面板。
3. 继续导航。
4. 按 `?`，查看完整键位图，再按 `?`。
5. 禁用并重新启用 **Settings → Vim → Key panel**。

预期：

- Key 面板隐藏时，四角准星仍然可见。
- 准星几何包围当前语义块、光标或精确范围。
- 常驻面板只报告已处理的按键；编辑器键入的文本绝不出现。
- 即使面板隐藏，`?` 也会临时打开完整的上下文命令图。
- 关闭命令图后返回仅准星的 HUD。
- Key 面板偏好独立于 Vim 控件和 Vim HUD 持久化。

## 旅程 8：安全退出 Vim

**用户意图：** 与普通 Web 控件交互或关闭 Vim，且不出现意外。

1. 按 `Tab` 和 `Shift+Tab`。
2. 在原生输入框或文本域中键入。
3. 用 `Enter` 激活原生链接或按钮。
4. 在设置中禁用 Vim 控件，然后在文档中键入 Vim 命令键。
5. 重新启用 Vim 控件并关闭设置。

预期：

- Tab 导航绝不被 Vim 消费。
- 输入框、文本域、contenteditable 区域、对话框和嵌入式编辑器保留原生键入。
- 原生链接和按钮保留原生激活。
- Vim 禁用时，不消费任何未修饰的 Vim 键，文档也不会成为焦点表面。
- 重新启用后恢复自动文档焦点，同时保留独立的 HUD 和 Key 面板偏好。

## 旅程 9：压测易竞态路径

**用户意图：** 像经验丰富的评审者一样快速导航。

1. 在散文、表格和代码上按住或快速重复 `j` 和 `k`。
2. 以打字速度混合 `gg`、`G`、单词、行和块跳转。
3. 连续打开并取消多个评论。
4. 保存评论，立即导航，然后创建另一个标注。

预期：

- 只有显式调用的操作才打开 UI。
- 导航键绝不泄漏到未请求的评论编辑器。
- 之前的选区在操作完成后不能重新打开编辑器。
- 焦点和准星状态绝不落后于可见目标。
- 页面在跟随目标时不振荡、跳动或模糊。

运行期间发现并修复了三个真实缺陷：

1. 原始 HTML 评论标记替换了选中的文本节点，导致保存后 Visual 状态指向过期范围。桥接现在在已提交的标注标记上恢复范围。
2. 原始 HTML 的 `y` 无法从不透明源沙箱写入。它现在向获得焦点的父查看器发送有界、源验证的复制消息，父查看器执行与 Markdown 相同的保焦点复制。
3. Vim 自动焦点激活时，键盘块覆盖层可能在视觉上遮挡嵌套的指针 Pinpoint 目标。指针悬停现在拥有经典 Pinpoint 覆盖层，直到下一个已处理的 Vim 命令，然后所有权立即返回键盘目标。

应用内自动化驱动在每个 macOS 布局上无法与物理浏览器输入完全相同地合成 `m` 和 `Space`。这两个命令通过真实 `Viewer`/高亮器集成和原始桥接 DOM 测试覆盖，这些测试断言共享标注工具栏以正确范围打开。
