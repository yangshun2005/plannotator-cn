# 提交列表视图（线性历史轨道）

状态：粗略规格，迭代中。不属于 PR #990 —— 独立分支/PR，基于 `feat/simple-git` 叠加（它建立在面板视图切换和 diff 类型接缝之上）。

## 是什么

代码审查的第三种左侧面板视图：当前分支的线性提交历史，最新在前 —— 即 `git log --oneline` 的可点击列表。

```
● a1b2c3d  fix stage button border        2h    (current)
○ cd79196  round-6 review fixes           5h
○ 42024ab  round-4 review fixes           1d
─── origin/main ───────────────────────────
○ 9bded34  chore: bump version            2d
```

点击某个提交会显示**该提交自身的 diff**（git-show 风格：该提交与其父提交对比）。每次点击相互独立 —— 这是"逐步回溯历史"，不是滑动式审查基线。since-base /"PR 会显示什么"的问题仍由 Git status 视图负责。

## UI

- 面板切换变为三个选项：`Git status | Commits | Tree`。（文本切换已上线；增加一个分段。若三个分段在 256px 头部中过于拥挤，回退为同样 10px 字号的 `Git status | Commits | Tree` —— 先测量。）
- 列表行：短 SHA、主题（截断）、相对时间。作者始终显示头像（2026-07-03 实机审查中修订 —— 原为：仅当与仓库用户不同时显示）。当前选中项有标记。
- 在分支与基线交汇处（`origin/main`，通过我们已解析的同一 merge-base）显示分隔行 —— 其上均为"你的"提交。
- 侧边栏是纯提交列表 —— 永远不会变成文件列表。点击提交会在中央停靠区以 ALL-FILES 视图（现有的 AllFilesCodeView 界面）打开该提交的完整 diff：所有文件在一个滚动文档中。无折叠面板、无下钻、无返回按钮。（2026-07-03 决定。）
- 深度：`--first-parent -50`，"Show more" 再追加 50。永远无图形、无拓扑。

## 服务端

- 新增 diff 模式 `commit:<sha>`（仅 git），沿用现有接缝：
  - patch：`git diff <sha>^ <sha>`（根提交：`git show` / 空树基线）
  - label：`Commit <shortsha> — <subject>`
  - fingerprint：sha 本身 —— 不可变，因此陈旧性探测很简单（除非 HEAD 移动且该提交从历史中消失，否则始终新鲜）
  - file-content：旧侧 `<sha>^`，新侧 `<sha>`
- 新增端点 `GET /api/commits?limit=&before=` → `[{ sha, shortSha, subject,
  author, authorEmail, committedAt, isHead, isPastBase, avatarUrl? }]`。基于与活动 diff 相同的 cwd/worktree 计算。
- `/api/diff/switch` 接受 `commit:<sha>` 作为 diffType。Sections sidecar：不生成（sections 仅限 since-base，不变）。
- 提交 diff 的暂存门控关闭（历史提交中无可暂存内容）。`isPathStageable` 已集中处理此逻辑。
- Ask AI 上下文：agent-review 消息机器获得提交模式 inspect 字符串（"this is commit <sha>, inspect with `git show <sha>`"）。
- 两种运行时（Bun + Pi）。jj/P4/workspace/PR 模式：不在范围内，切换隐藏（同 `sectionsCapable` 风格门控，仅 git 本地会话）。

## 持久化

- （2026-07-03 实机审查后两次修订。）头部切换对所有视图完全 SESSION-SCOPED —— 永不写入 `reviewPanelView` 或 `defaultDiffType`。初始视图仅在 Settings 或首次运行对话框中设置（它们保留 sections⟺since-base 耦合）。`reviewPanelView` 保持 `'sections' | 'tree'`：Commits 永远不能作为初始视图 —— 审查始终以文件打开。陈旧的 `'commits'` cookie 视为未设置。永不持久化 sha（变基后可能不存在）。
