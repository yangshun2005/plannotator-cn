# Spec: 引导式审查 (v1)

日期：2026-07-02 · 状态：迭代草案
ADR：`adr/decisions/006-guided-review-first-class-feature-20260702-192821.md`
综合文档：`adr/research/synthesis-guided-review-20260702-195351.md`

## 概述

`guide` agent-job provider 为当前变更集生成分章节的审查——核心实现在前，胶水代码在后。引导以屏幕接管形式渲染（隐藏文件树 + dock，保留头部 + 右侧边栏）：有序章节，每节将一段文字概述与可实时标注的逐文件 diff 配对。在引导中所做的标注就是普通的 `CodeAnnotation`——相同状态，相同的 Send Feedback 载荷。

## 数据模型

`packages/shared/guide.ts`（通过 vendor.sh 同步到 Pi）：

```ts
interface GuideDiffRef {
  file: string;          // repo-relative path, must match a DiffFile.path
  lineStart?: number;    // optional highlight hint (new side), not a slicing boundary
  lineEnd?: number;
  note?: string;         // one-line caption for this diff within the section
}

interface GuideSection {
  title: string;         // "Payment Localization Module"
  overview: string;      // markdown prose: what this part is, why it exists
  kind: "core" | "consequence" | "support";  // drives ordering + glue separation
  diffs: GuideDiffRef[]; // 1..n
}

interface CodeGuideOutput {
  title: string;         // from PR when present, else derived from changes
  intent: string;        // 1-2 sentence framing shown under the title
  sections: GuideSection[];   // ordered: core first, support last
  unplacedFiles?: string[];   // changed files the model didn't place (rendered in a
                              // trailing "Everything else" section — coverage guarantee)
}

type CodeGuideData = CodeGuideOutput & { reviewed: boolean[] };  // per-section state
```

服务端接收时校验（fail-closed，沿用 tour 先例）：
- 零章节 → 任务 `failed`（`GUIDE_EMPTY_OUTPUT_ERROR`）
- `diffs[].file` 不在当前 `DiffFile` 集合中 → 整个引用被丢弃
  （伪造路径永不出现）；`unplacedFiles` 只包含模型自己未放置、或从未落入
  任何章节的真实变更文件
- 每个变更文件必须在 sections + unplacedFiles 中恰好出现一次
  （服务端通过集合比对强制执行，模型被要求但不被信任）

## 服务端

新模块 `packages/server/guide/guide-review.ts`（镜像 `tour/tour-review.ts`）：
- `GUIDE_REVIEW_PROMPT` — 系统提示词。核心指令：按工作被推理的顺序排列章节；
  将胶水/低信号变更分离到 `support` 章节；概述解释*为什么*，而非逐行*是什么*。
  与 `TOUR_REVIEW_PROMPT` 相同的纪律（适用处禁止破折号/emoji 等规则），但采用引导语气。
- `GUIDE_SCHEMA_JSON` — `CodeGuideOutput` 的 JSON schema。
- `buildGuideUserMessage` — 复用 diff 上下文框架模式
  （`agent-review-message.ts` 风格）+ 变更文件列表及逐文件统计，以便
  模型针对真实文件集规划放置。
- `buildGuideClaudeCommand` / `buildGuideCodexCommand` — 复制 tour 的 flag 集
  （Claude：`--json-schema`、stream-json、只读 allowedTools；Codex：
  `--output-schema` + 输出文件、`--full-auto --ephemeral`）。
- `createGuideSession()` — 内存中 `guideResults: Map<jobId, CodeGuideOutput>` +
  `guideReviewed: Map<jobId, boolean[]>`；`getGuide`、`saveReviewed`、`buildCommand`、
  `onJobComplete`（解析器：Claude 用 stream，Codex 用文件）。

集成（现有接缝）：
- `packages/server/agent-jobs.ts`：将 `"guide"` 加入 `SERVER_BUILT_PROVIDERS`；
  capabilities 条目 `guide: claude || codex`（与 tour 相同规则，agent-jobs.ts:161）。
  无需修改日志格式化器：格式化器依据 `spawnOptions?.engine ===
  "claude"`（agent-jobs.ts:314），引导的 buildCommand 结果通过返回 `engine`
  满足此条件，tour 风格。
- `packages/server/review.ts`：在 `buildCommand` /
  `onJobComplete` 中于 tour 分支旁添加 `provider === "guide"` 分支（review.ts:690-700、901-914）；在 tour 路由旁
  添加 `GET /api/guide/:jobId` 和 `PUT /api/guide/:jobId/reviewed` 路由
  （review.ts:1016-1034）。Profile 解析随行未使用，tour 风格。
- Pi 镜像：在 `apps/pi-extension/vendor.sh` 中，将 `guide` 加入扁平共享模块
  列表（第 10 行，紧邻 `tour`），并为 `guide-review` 复制 `tour-review` 特殊块
  （第 30-38 行）（父级相对路径 + `@plannotator/shared/guide`
  导入重写）；在 `apps/pi-extension/server/serverReview.ts` 中手动镜像
  两个路由 + provider 分支。

## 客户端（`packages/review-editor`）

**状态（App.tsx）：**
- `guideOpen: boolean`，紧邻 `isFileTreeOpen`（App.tsx:216）。
- `activeGuideJobId: string | null` — 最近完成的 `guide` 任务；完成
  通过扩展 tour 自动打开 effect 模式（App.tsx:780-792）并添加 ref
  `Set` 去重来观察。首次完成时自动切换 `guideOpen = true`（镜像 tour
  自动打开；构建时确认自动接管是否合适，还是用徽章脉冲）。
- 接管机制：当 `guideOpen` 时，**CSS 隐藏** dock 包装器（App.tsx:2793）和文件树；
  绝不卸载 `<DockviewReact>`（布局丢失，已由
  files.length===0 分支证明）。引导屏幕作为主内容行中的同级分支渲染
  （App.tsx:2671+）。右侧边栏不动。
- 焦点仲裁修复（已验证比 spike 更简单）：`focusedFilePath` 在
  ReviewStateContext 填充时计算一次（`App.tsx:1778`、`files[activeFileIndex]`），
  每个 dock 面板从中派生 `isFocused`（`ReviewDiffPanel.tsx:22`）。当 `guideOpen` 时在那里将其置空——一行，
  所有 CSS 隐藏的 dock DiffViewer 在源头失去焦点声明。引导侧实例按章节
  可见性在彼此之间仲裁。

**头部：** `Guide` 徽章紧跟在文件树切换分隔符之后
（App.tsx:2274），样式参照目标下拉 pill（App.tsx:2334-2348）；`guideOpen` 时
为激活状态。快捷键 `Mod+Shift+G` 加入 `reviewEditorShortcuts`
（先例：toggleTour，shortcuts.ts:58-76）。

**新组件（`components/guide/`）：**
- `GuideScreen` — 接管根；分支：空状态 / 生成中 / 引导视图。
- `GuideEmptyState` — Notion 风格页面；引擎/模型/effort 通过 `useAgentSettings`
  中新的 `guide*` 切片（cookie hook，镜像 tour 切片）渲染，使用从 AgentsTab
  提升出的选择器原语（`ConfigRow`、`SegmentedPicker`、
  `SelectMenu` → 共享文件）；Generate 按钮从单一 `useAgentJobs()` 实例调用
  App 级 `launchJob`（不建立第二个 SSE 连接）。
- `GuideGenerating` — 任务状态 + 通过现有 jobs/jobLogs props 实时日志窥视；
  取消 = 现有 killJob。
- `GuideView` — 标题、元信息、有序 `GuideSectionCard` + 来自 `unplacedFiles`
  的尾部"其他所有内容"。
- `GuideSectionCard` — 标题、`NN / MM`、Reviewed 复选框（勾选 → 折叠为
  单行）、概述（现有 markdown 渲染），然后每个 `GuideDiffRef` 一个
  `GuideDiffSection`。
- `GuideDiffSection` — 轻量 `ReviewDiffPanel` 风格适配器：解析
  `files.find(f => f.path === ref.file)`，挂载一个 `DiffViewer` + `ToolbarHost`

  漂移优雅降级）。
- `useGuideData` hook — `useTourData` 形状的副本：fetch `GET /api/guide/:jobId`，
  防抖 `PUT .../reviewed` 并 keepalive 刷新；外加一个演示引导
  （`demoGuide.ts`），置于与 `DEMO_TOUR_ID` 相同的开发开关模式之后。

**AgentsTab：** 将 `guide` 添加为可启动模式（类似 tour），以便侧边栏也能
启动/重启引导；引导任务显示在任务列表中；已完成引导任务的卡片
获得"Open guide"操作 → `guideOpen`。

## Reviewed 状态与陈旧语义

- Reviewed 复选框按章节（v1：无逐 diff 复选框——从线框图中砍掉
  以保持状态模型最小；若感觉不足再重新考虑）。
- Reviewed 状态按 jobId 键控，内存中（tour 清单先例）。重新生成
  创建新任务 → 全新 reviewed 状态，旧引导仍可通过旧 jobId 获取。
- Diff 陈旧：引导渲染*当前* `files` 数组所持有的内容——如果
  用户在生成后刷新/切换 diff，仍能解析的引用渲染
  新内容；不能解析的显示 outdated 标签和"Regenerate guide"
  操作。引导从不固定自己的补丁副本。

## 构建顺序（每步可交付）

1. 共享类型 + 服务端模块 + provider 分支 + 路由（+ 演示引导 fixture）。
2. 头部徽章 + 接管分支 + GuideScreen 空/生成状态 + 启动
   （设置切片 + 提升的选择器原语）。
3. GuideView/SectionCard/DiffSection 及标注接线 + reviewed 持久化 +
   焦点仲裁修复。
4. AgentsTab 集成、Pi 镜像、`bun run --cwd apps/review build && bun run
   build:hook` 流水线检查、文档（CLAUDE.md 端点表）。
