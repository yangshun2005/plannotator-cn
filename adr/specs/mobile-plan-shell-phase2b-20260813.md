## 决策

阶段 2B 将 Plan 评审与文档标注从响应式桌面布局转变为阅读优先的紧凑触控体验。它不重新设计选择的工作方式。它移除同时出现的移动端界面元素，恢复当前受阻的文件夹/多文件流程，使直接编辑的完成操作可达，并将标注、AI、导航和终端评审操作保留为有意触发的临时任务。

在紧凑触控下，Plan 产物仍是普通的文档滚动页面。该滚动归属方和非吸顶的顶部边缘是阶段 1 已接受的行为：真实 iPhone 评审证明，它们能让 Safari 的顶部和底部控件收缩，同时文档仍可见于浏览器材质之后。阶段 2B 不得重新引入固定或吸顶的视口边缘应用栏。

期望的感受是**平静、清晰、可控**。评审者应打开 URL 后立即明白自己在评审什么，无需先关闭辅助 UI 即可阅读，有意进入标注或编辑，并在末尾到达清晰的完成界面。

## 方法论

实现遵循移动端 spike 确立的审计方法：

1. 以真实 Mobile Safari 行为为准，响应式 Chromium 仅作预检。
2. 分离观察、解读、实现和验证。
3. 盘点每个常驻区域，并归入四种结果之一：保留在产物中、按上下文暴露、移入临时界面，或在紧凑触控下移除。
4. 将紧凑体验建模为显式的 UI 状态，而非可能同时重新打开多个桌面侧栏的独立布尔值。
5. 保留文档作为滚动归属方，并在移动 UI 之前追踪每个导航、焦点、选择、编辑、草稿和完成依赖。
6. 以可用宽度加粗指针能力作为紧凑呈现的门禁。窄的精细指针桌面窗口保留桌面行为。
7. 分三个检查点实现和评审阶段 2B，每个检查点均可独立使用和回退。
8. 关闭阶段前要求真实 iPhone 和 iPad 证据；每个检查点都要求桌面几何和偏好控件。

## 紧凑触控激活

使用共享的 `useCompactTouchLayout(1024)` 能力。当可用视口宽度不超过 1024 CSS px 且设备暴露 `any-pointer: coarse` 时，紧凑外壳激活。

- 手机竖屏和横屏：紧凑。
- iPad 竖屏和受限分屏视图：紧凑。
- 大 iPad 横屏在可用宽度超过 1024 px 时可保留桌面。
- 仅有精细指针的窄笔记本窗口：桌面。
- 混合 iPad 即使连接触控板仍保持触控安全，因为 `any-pointer: coarse` 继续匹配。

紧凑呈现状态为会话本地。它不得写入桌面侧栏、右侧面板、输入法、视图模式或吸顶操作偏好。

## 信息架构

### 单一前台任务

紧凑 Plan 外壳一次只有一个前台状态：

| 状态 | 主要内容 | 退出行为 |
|---|---|---|
| `artifact` | Plan/文档阅读、上下文标注或直接编辑 | 仅会话终端操作 |
| `navigator(tab)` | Contents、Files、Versions、Messages 或 Archive | 关闭或选择目标 |
| `annotations` | 现有反馈和直接编辑摘要 | 关闭返回同一产物位置 |
| `ai` | Ask AI 对话 | 关闭返回同一产物位置 |
| `review` | 标注摘要加 Close / Send Feedback / Approve 策略 | 取消返回产物；终端操作使用现有确认逻辑 |

历史布尔值可在内部保留供桌面使用，但紧凑渲染必须从单一前台状态派生。打开一个临时界面会关闭前一个。旋转不得复活过期的侧栏或先前的临时界面。

模态确认仍位于这些状态之上，并保留阶段 1 的共享可见视口、焦点约束和草稿契约。

### 紧凑应用头部

紧凑头部是一个 52 px 的正常流行；它随页面滚走。它包含三个几何稳定的区域：

1. **Navigate** — 在最近可用的标签页打开导航器（未选择文件夹会话时为 `Files`，否则为最后一个会话本地标签页）。
2. **文档标识** — 当前基名或 plan 标识，完整路径可供无障碍使用，受限时采用前导省略号处理。
3. **Options** — 打开紧凑操作菜单，包含现有终端决策、可用时的 Edit，以及次要应用操作。Annotations 和 Ask AI 在检查点 2B.3 加入此菜单。

头部不同时显示 Send Feedback、Approve、Annotations、AI 和 Options 控件。它不显示桌面键盘快捷键。品牌信息可在 Options/关于上下文中获取，而不挤占文档标识。

桌面 `AppHeader` 几何和操作位置保持不变。

### 移动端导航器

移动端导航器复用 `SidebarContainer` 的内容；它不是第二个文件/版本/归档实现。新的呈现接缝让同一组件渲染：

- 现有的吸顶、可调整大小的桌面侧栏；或
- 受可见视口约束的紧凑界面，带 52 px 标题/关闭行、触控安全的标签控件和一个滚动区域。

可用标签保持上下文相关：Contents、Versions、Files、Messages 和 Archive。Agent 终端控件不会在此导航阶段被悄悄拉入。

选择规则：

- 选择 Contents 目标会关闭导航器，并使用现有文档视口契约滚动文档。
- 选择文件/消息/归档目标会在新产物就绪后关闭导航器，并将其标题放入头部。
- 切换文档不得丢弃标注、文件编辑缓冲区或草稿。现有编辑兼容性守卫仍为准。
- 未选择即返回/关闭会保留产物及其滚动位置。
- 文件夹空状态变为可操作的 `Choose a file` 界面，打开 `navigator('files')`；它绝不指示用户去寻找隐藏的侧栏。

### 阅读与标注界面元素

紧凑触控以 `artifact` 状态到达，文档优先。现有输入法和标注语义保留，但其完整矩阵不常驻展开。

- 紧凑触控始终呈现现有的 Markup 语义：选择目标后显示上下文 Copy / Delete / Comment / Label 操作，而非要求常驻操作模式行。这是紧凑呈现决策，绝不覆盖已保存的桌面操作模式。
- 空闲状态显示一个显式的 `Annotate · <method>` 入口。
- 打开后仅显示 `Select text` 和 `Pinpoint`。Pinpoint 命名为单块点击方法；Select text 命名为拖选文本方法。选择为会话本地，绝不覆盖已保存的桌面输入法。
- Markup / Comment / Redline / Label 操作在有效目标存在后按上下文出现，而非到达时作为常驻第二工具栏。
- 紧凑控件使用共享的 44 px 触控契约和即时按压反馈。它们不得依赖悬停。
- Command/Enter 字形和其他仅桌面快捷键教学在粗指针紧凑布局中隐藏。硬件键盘快捷键仍然有效。
- 文档滚动拥有紧凑页面期间，重复的吸顶/固定操作通道保持禁用。

多块累积、原生 Safari 选择冲突和 Pierre 行范围手势仍属阶段 3。阶段 2B 补丁不得用 CSS 掩盖这些未解决的语义。

### 文档卡片与直接编辑

Wide 和 Focus 是桌面工作区呈现选择。它们在紧凑触控上不显示——不在卡片上方，也不在 Options 中——因为手机已将可用宽度给产物，且没有可聚焦移开的并排面板。

直接编辑仍受支持：

- `Edit` 可从 Options 和现有文档上下文中到达（在仍清晰处）。
- 编辑开始后，稳定的文档流内编辑行位于编辑器之前，标明文件及保存状态。
- Done 和 Cancel/Discard 在该行中使用显式、触控安全的控件。
- 该行参与正常文档流；它绝不定位在 `-top-5`、被视口裁剪或附着于 Safari 边缘。
- 保存、Done、文件切换、外部变更协调和未保存编辑确认继续使用现有处理器。阶段 2B 移动其 UI，但不分叉其状态机。
- 打开软键盘必须保留阶段 1 的 16 px 输入、可见视口、草稿和旋转行为。

### 辅助界面

Annotations 和 Ask AI 在紧凑触控上是临时前台状态。它们打开时在视觉上替换产物；绝不成为缩小产物的固定同级元素。

- 新的紧凑到达会关闭两者，除非显式深链接请求其一。
- 打开或关闭它们不会改变已保存的桌面右侧面板状态。
- 每个都有可见的 44 px 关闭目标和单一内部滚动归属方。
- 返回时恢复先前的文档和滚动位置。
- AI 提供商/模型配置保留在其既有界面中；阶段 2B 不发明另一个提供商选择器。

### 完成

终端操作必须有意触发，且不重新引入固定边缘界面元素。

- 产物之后出现正常流的完成块。它报告当前反馈计数/状态并打开 `review`。
- Options 为在产物末尾之前完成的评审者暴露相同的 `Review` 入口。这是同一界面的两个入口，而非重复的操作实现。
- 评审界面根据当前会话模式、门禁策略、回调策略、未发送反馈守卫和标注状态拥有 Close、Send Feedback 和 Approve。
- 高风险操作保留现有确认。不要将 Approve 和类似丢弃的操作放在密集导航目标旁边。
- 本阶段不发布固定/吸顶底部栏。它会危及阶段 1 已解决的 Safari 边缘行为，且在真实原型证明其价值超出文档流完成模型之前没有必要。

## 检查点与评审门禁

### 2B.1 — 导航器与阅读优先到达

实现紧凑前台状态、移动端 `SidebarContainer` 呈现、Navigate 头部入口、文件夹空状态操作，以及关闭辅助侧栏的紧凑到达策略。

真实设备门禁：

1. 在 iPhone 上打开 `annotate <folder> --tailscale`。
2. 选择一个 Markdown 文件，返回 Files，然后选择一个 HTML 或第二个文本文件。
3. 确认选择后导航关闭，且标注/草稿保留。
4. 打开普通 Plan 评审，确认产物——而非 Ask AI 或侧栏——是第一个界面。
5. 旋转并确认没有桌面侧栏出现。

真实设备修正：

- iPhone 评审发现，选择文件夹文件后，导航器背后的文档明显改变，但导航器保持打开。过渡闪烁是因为它短暂关闭后又返回。
- 选择处理器正确关闭了紧凑前台状态；异步文档激活随后调用了 `useLinkedDoc` 的现有桌面指令来打开 Files 侧栏。在紧凑触控上，该桌面副作用在目标加载后重新打开了导航器。
- 紧凑文档激活现在将前台导航留给紧凑状态所有者。点击文件关闭导航器，后续激活无法复活它；桌面仍打开其现有侧栏标签页。
- 全应用粗指针测试通过共享后端加载真实文件树，选择文件，等待 `/api/doc`，并证明所选文档和文件名渲染时导航器保持关闭。
- 后续真实设备冷加载评审暴露了第二个过渡缺陷：导航器在第一个 `/api/doc` 请求完成前关闭，短暂显示文件夹落地页及其 `Choose a file` 操作。热文件切换足够快，掩盖了相同的顺序错误。
- 紧凑文件选择现在保持 Files 可见，将所选目标标记为 `Opening…`，并在文档激活成功前阻止竞争选择。然后关闭发起导航器；加载失败则保持 Files 打开以便重试。桌面保留其现有异步侧栏行为。
- 全应用测试现在将 `/api/doc` 置于有意门禁之后，证明导航器保持可见，所选文件在整个延迟期间处于忙碌/禁用状态，然后在成功激活后关闭。

### 2B.2 — 紧凑文档界面元素与直接编辑

实现三区域头部、空闲标注入口/上下文工具、Options 中的次要视图选择，以及文档流内编辑行。

真实设备门禁：

1. 阅读长 plan，确认头部滚走，同时两个 Safari 栏保持已接受的收缩行为。
2. 通过 Annotate 进入 Pinpoint，选择一个段落，保存评论。此处明确不评判多块选择。
3. 进入直接编辑，用软键盘输入，保存，旋转，然后 Done。
4. 确认每个编辑控件完全可见且至少 44 px 高。
5. 确认没有常驻重复工具栏或快捷键字形主导到达。

实现检查点：

- 紧凑头部现为稳定的 52 px 网格，包含 44 px 导航目标、居中的当前文档基名和 44 px Options 目标。它保持正常流，因此已接受的 Safari 文档滚动行为不变。
- Close / Send Feedback / Approve、回调决策、归档决策和目标设置决策仅在紧凑触控上移入 Options。每个项目调用现有处理器，因此保留既有的确认、未保存文件、传输和 agent 验证行为。
- 常驻 Select / Pinpoint 和 Markup / Comment / Redline / Label 组替换为一个 `Annotate · <method>` 展开项。展开的选择仅为 Select text 和 Pinpoint；上下文反馈操作仍来自现有目标工具栏。
- 紧凑标注始终使用 Markup 语义，不写入已保存的桌面操作模式。紧凑输入法更改也仅限会话。
- Wide 和 Focus 在紧凑触控上缺失。桌面保持其现有绝对微控件和行为不变。
- Edit 移入 Options。编辑开始后，编辑器上方的正常流行标明文档，并通过现有编辑状态机暴露源文件 Save 以及 Done/Cancel/两步 Discard。
- 桌面渲染预检保留了现有 48 px flex 头部、完整工具条、Wide / Focus / Edit 控件和精确页面宽度，无溢出。窄精细指针控件也保留桌面组合。紧凑粗指针渲染仍为真实设备门禁。
- 全应用粗指针集成测试现在证明真实紧凑路由：三区域头部中的当前文件名、一个标注展开项、无常驻桌面工具矩阵、仅会话输入法更改、Options 中的评审决策和 Edit，以及文档流内编辑行。十八个聚焦 DOM 测试和 72 个编辑器测试通过，同时共享类型检查、生产 UI CSS、Hook 和 OpenCode 构建以及 `git diff --check` 通过。

### 2B.3 — 辅助与完成界面

实现临时 Annotations/AI 状态、文档流内完成块，以及从产物末尾和 Options 到达的单一 Review 界面。

真实设备门禁：

1. 打开和关闭 Annotations 和 AI；确认各自替换而非挤压产物，并返回同一位置。
2. 添加反馈，到达完成块，打开 Review。
3. 通过现有确认路径执行 Send Feedback 或 Approve。
4. 将手机后台/恢复，并在有未发送反馈时旋转一次。
5. 在桌面宽度重新加载，确认已保存的侧栏/右侧面板布局、吸顶操作、头部操作和编辑控件不变。

实现检查点：

- Annotations 和 Ask AI 现在作为互斥、受可见视口约束的紧凑阶段打开。它们激活时替换产物，保持一个内部滚动归属方，并在关闭时将焦点返回打开控件。
- 共享标注时间线增加了嵌入式呈现接缝；其现有桌面面板几何、背景、头部和持久化打开状态保持不变。
- 正常流完成块跟随符合条件的 Plan 和文档产物。它汇总当前反馈状态并打开与 Options 暴露的相同 Review 界面；编辑、diff、目标、HTML 和未选择文件夹状态不渲染它。
- Review 复用现有决策回调和策略，而非添加另一个提交状态机。带反馈的会话优先 Send Feedback，可批准的干净会话优先 Approve，仅关闭会话保留其既有退出行为。
- 紧凑阶段使用阶段 1 的可见视口和安全区域契约、44 px 触控目标、即时交互反馈、焦点约束和 16 px Ask AI 输入。未引入固定或吸顶的 Safari 边缘控件。
- 全应用粗指针测试覆盖互斥、关闭行为、文档末尾入口、决策提交、编辑排除，以及紧凑 Options 中缺失仅桌面终端操作。共享组件测试覆盖焦点约束、嵌入式标注呈现、评审排序和终端操作语义。
- 编辑器/UI DOM 套件通过 111 个测试、412 个期望。共享类型检查、生产 UI CSS、Hook 和 OpenCode 构建通过，以及 `git diff --check`。精细指针渲染预检保留了现有桌面侧栏/右侧面板组合，无紧凑完成块或全阶段覆盖层。

阶段 2B 仅在全部三个检查点在真实 iPhone 和相关 iPad 矩阵上通过后才算通过。浏览器预检不能关闭阶段。
