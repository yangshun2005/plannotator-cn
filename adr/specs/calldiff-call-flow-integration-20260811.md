# 可选的 CallDiff 调用流审查

- 状态：已实现（实验性，默认关闭）
- 日期：2026-08-11
- 外部引擎：CallDiff 0.6.0，提交 `2086f6e4e9ed3c410bba7c94ca3dde77791b1956`（2026-10-29 从 0.4.1 的 `a3194d20ca91ef6a314273d634e9b9c0db1c2707` 重新固定）
- 用户可见名称：**Call flow**

## 决策

Plannotator 代码审查提供两项独立的可选分析：

- **语义变更**（默认开启），由 `sem` 驱动。
- **调用流**（默认关闭），由 CallDiff 驱动。

调用流基于同一份以快照为键的结果提供两个视图：

1. 审查级的 **Call flow** Dock 面板；
2. 文件头部的按文件 **`flow N`** Lens。

关闭调用流会移除这两个界面并停止分析。语义变更保留其现有的 Dock 和 Lens，但现在可以独立关闭。两项设置一起持久化在 `reviewAnalysis` 下，一个开关不会覆盖另一个。

## CallDiff 的作用

CallDiff 比较两个 Git 提交处的完整源码树。它使用 Tree-sitter 提取具名可调用对象和有序的调用/分支步骤，推断受变更调用影响的入口路径，递归展开有界调用树，并将节点标记为 `same`、`added` 或 `removed`。源码位置标识定义和调用点。

CallDiff 是语法证据，不是运行时追踪。它不提供类型或导入解析、数据流、副作用、严重性、置信度、测试覆盖率或动态分派的证明。重复的裸符号名可能产生歧义，移动或重排可能表现为删除/新增对。因此产品文案使用“推断的入口路径”和“变更的调用流步骤”。

CallDiff 0.6.0 宣称支持 23 种提取器模式。Plannotator 使用其中 22 种：JavaScript/JSX 与 TypeScript/TSX 共享一个核心语法族，其余映射到 19 个可独立安装的语法包（C++ 包含 CUDA `.cu`/`.cuh`）。0.6.0 新增的 Perl 被排除，因为 `tree-sitter-perl` 不提供预编译二进制，其包需要 C 编译器。

## 运行时边界

npm 包落后于上游（首次固定的 `calldiff@0.4.1` 早于源码位置输出；0.6.0 未发布到 npm）。因此 Plannotator 安装上述提交处的精确上游源码归档，校验其 SHA-512 完整性，并在安装时编译一次。

安装严格基于同意且具有选择性。默认不会安装调用流。调用流开关即同意：其引导对话框和设置文案会说明当前补丁的语言族、仓库自有大小估算总量、Node.js 22.18+ 要求以及按需自动安装语言。开启后，会将变更扩展名映射到语言族，并启动一个后台安装，包含裁剪后的核心（CallDiff、Tree-sitter、JavaScript 和 TypeScript）以及该审查恰好缺失的语法包。Dock 变为非阻塞的分阶段进度界面，并在同一会话内移交分析；主路径中没有第二次安装确认。

后续审查会立即分析已安装语言，同时为缺失语言返回明确的跳过文件元数据。同一同意会自动启动这些包，安静的内联通知报告进度，完成后重跑同一快照。每个目标在每个审查会话（一次页面加载）中只自动尝试一次：预检、下载、校验或构建失败不会在该会话内自动循环。面板和侧边栏安静地展示失败，显式重试可以再次启动该目标。Dock 的详情区域列出所有支持的语言、累计估算已安装大小以及提前安装控件。v1 中包不可单独移除；卸载会移除整个受管理的调用流目录树。

其他入口包括无头核心安装（`plannotator install-runtime call-flow`）和安装器核心选择加入（`--with-call-flow` / `-WithCallFlow`、`PLANNOTATOR_INSTALL_CALLDIFF=1`，或 config.json 中的 `{ "installCallFlow": true }`；标志 > 环境变量 > 配置）。语言包仍可从审查 UI 中选择，当前补丁提供权威需求。最小安装始终排除调用流。

受管理运行时位于：

```text
~/.plannotator/vendor/call-flow/calldiff-0.6.0
```

其契约如下：

- Node.js 22.18 或更新（CallDiff 的 `engines` 下限）；
- 精确的 CallDiff 源码提交和归档完整性；
- 一个小型核心，包含 Tree-sitter 和 JavaScript/TypeScript 语法的精确直接版本；
- 每个可选语法包一个仓库提交的 `package-lock.json`，包含精确包版本和镜像仓库完整性哈希；
- 可选包 tarball 下载到内存，对照这些仓库自有 SHA-512 值校验后才暴露给全新的私有 npm 缓存；`npm ci` 在离线模式下使用该缓存；
- 仅在裁剪后的包通过 CallDiff 成功加载后才写入锁标记；没有该精确标记的文件夹视为未安装；
- 在任何显式原生重建之前执行 `npm ci --ignore-scripts`，适用于核心和每个包；
- 安装后裁剪 TypeScript/Node 构建工具、生成的解析器源码、外部平台预构建产物和 node-gyp 中间产物；本地编译的最终 `.node` 插件保留；
- 数据目录安装租约在审查服务器进程间串行化核心修复和包发布；超过 30 分钟的崩溃租约可恢复，而每进程协调器仍在单个服务器内去重目标；
- 审查期间不安装包或访问网络：服务器预检在 spawn 前解析缺失包，worker 在导入 CallDiff 前验证 CallDiff、Tree-sitter、每个核心语法以及每个相关可选语法的精确版本，`CALLDIFF_GRAMMAR_CACHE` 仅指向受管理存储，设置 npm 离线标志，PATH 前置的 npm 拦截器使 CallDiff 的上游惰性安装器在裁剪后验证和分析期间均不可达；
- 短生命周期 Node worker，512 MB 堆、45 秒超时、12 MB 输出限制；
- 解析输出限制为 100 棵树、5,000 个节点、深度 32 和 100 条诊断；
- 不受信任的源码路径在绝对路径或父级遍历时被拒绝。

2026-08-11 在 macOS arm64、Node 24.15.0 上固定安装后测量：核心从裁剪前的 94,408,476 字节缩减到 4,649,257 字节；代表性 Python 包从 7,513,587 字节缩减到 527,081 字节。该平台上全部 19 个可选包加核心占用 71,925,356 字节。UI 估算为每个包实测裁剪大小向上取整；原生产物大小可能因平台略有差异。

`PLANNOTATOR_CALLDIFF_PATH` 是开发覆盖项，用于已构建且其可选语法已在其自身 `node_modules` 下可用的 CallDiff 包。覆盖项从不提供受管理包安装：无效覆盖状态会说明其直接恢复方式，而不是展示无法修复的安装漏斗。正常卸载会移除受管理的 `vendor/call-flow` 目录，同时保留未知 vendor 条目。原 `PLANNOTATOR_SKIP_CALLDIFF_INSTALL` 退出选项已删除：退出默认关闭的安装毫无意义。

## 精确快照物化

CallDiff 需要两个不可变提交。快照物化是 VCS 提供方能力：每个提供方负责将其审查模式映射到不可变 Git 提交对，而调用流只接收不透明快照源。对于补丁支持的视图，Plannotator 从不将 CallDiff 指向可变工作树。Git 提供方创建临时共享克隆，在正确基线处播种临时索引，应用精确可见补丁，并使用 `git commit-tree` 创建不可达合成提交。清理会移除临时克隆。用户仓库中的任何 ref、索引或工作树都不会改变。

在 spawn worker 之前，Plannotator 按支持的扩展名对每个变更路径的两侧分组。然后列出两个不可变快照，并向 CallDiff 传递精确路径过滤器，包含与补丁相关的已安装语言族中的所有文件。这保留了完整的同语言仓库调用图，而不是将分析缩减为变更文件，同时防止仓库中其他地方无关的不支持语言到达 CallDiff 的惰性语法加载器。

| 审查视图 | CallDiff `from` | CallDiff `to` |
| --- | --- | --- |
| 自基线以来 | merge-base(base, HEAD) | 包含可见补丁的合成提交 |
| 未提交 | HEAD | 包含可见补丁的合成提交 |
| 已暂存 | HEAD | 包含可见补丁的合成提交 |
| 未暂存 | 合成暂存快照 | 合成快照加可见未暂存补丁 |
| 分支 | 选定基线提交 | HEAD |
| 合并基线 | merge-base(base, HEAD) | HEAD |
| 最后一次提交 | HEAD 的第一个父提交 | HEAD |
| 提交轨 | 选定提交的第一个父提交 | 选定提交 |
| PR 层/完整栈 | 本地可用的精确 base/head 对 | 本地可用的精确 head |
| JJ 当前变更 | `@` 的第一个父提交 | `@` |
| JJ 最后一次变更 | `@` 的第一个父提交的第一个父提交 | `@` 的第一个父提交 |
| JJ 工作线 | 选定修订的工作线基线 | `@` |
| JJ 演化 | 选定的历史演化条目 | `@` |

Jujutsu 父级跳转针对仓库遍历，而不是写成 revset。`@-` 是 `parents(@)`，因此在合并修订上 `@-` 和 `parents(@-)` 都解析为多个修订，`jj diff` 会直接拒绝该命令，即使可见的 `jj diff -r @` 审查仍能渲染。每次跳转解析第一个父提交的提交 id，这与 `getJjFileContentsForDiff` 已展开合并的一侧相同，因此调用流和文件展开一致。

Jujutsu 快照请求 `jj diff --git`，限制为分析语言族中的源扩展名，使用锚定仓库根的 `root-glob-i:` 文件集，因此从子目录启动的审查不会静默丢弃其上方的源文件。基线侧整体物化（`root()` 到基线修订）；第二侧是该树加上两个修订之间的变更文件增量，因此物化成本随审查而非仓库增长，当增量无法重放时回退到全树第二遍。读取由运行时在流式传输时限制为 64 MB，而不是事后测量。每个过滤后的树变成不可达合成 Git 提交，不改变被审查的检出；如果 JJ 修订在物化期间移动，现有快照指纹检查会拒绝结果。二进制条目被省略，因为 CallDiff 消费可解析源文本，而 Jujutsu 的 Git 格式 diff 不携带二进制载荷；文本文件、符号链接、可执行模式和删除保留其 Git 补丁语义。All Files 快照没有有意义的提交基线，明确不支持。GitButler、Perforce、嵌套工作区聚合以及无本地检出的托管 PR 分析在此版本中也不支持。

## 服务器和 API 契约

Bun 和 Pi 暴露相同的端点和响应形状。

- 每个初始和切换的 diff 载荷都声明 `semanticDiff` 和 `callFlow` 能力状态。
- `POST /api/review-analysis` 验证并持久化独立布尔设置，返回新声明，并将变更应用到活动会话。
- `GET /api/review-analysis` 刷新声明而不加入设置变更纪元。安装完成使用此只读路由，重试瞬时失败，因此不会取代或静默丢失并发的开关变更。
- `GET /api/call-flow?snapshot=<snapshotId>` 仅分析活动快照。
- 快照不匹配或执行期间仓库变更返回结构化 `stale` 状态，HTTP 409 和 `Cache-Control: no-store`。
- 禁用、不支持、不可用、过期、错误和成功结果保持为不同的领域状态。
- `POST /api/call-flow/install` 接受 `{ languageIds?: CallFlowLanguageId[] }`。同意驱动的客户端提交服务器编写的当前审查目标 id；省略列表仍解析权威当前审查计划，手动语言列表提供显式提前安装 id。需要时前置核心。一个协调器去重目标，将新目标排队到活动的单次飞行，并报告当前包。任何下载前运行 Node.js 22.18+ 预检；缺失或过旧的 Node 是独立的即时 `{ state: "error", reason: "node-unavailable" | "node-version" }`。同源守卫仍然强制。
- `GET /api/call-flow/install-status` 报告 `{ state: "idle" | "running" | "done" | "error", stage?, languageIds?, currentLanguageId?, error?, reason? }`，`stage` 依次推进 `downloading`、`verifying`、`installing-deps`、`building`。`error` 持续到下一次安装 POST 重试。完成会取消旧工作并使两个运行时中的运行时探测及成功/失败结果缓存失效，因此同一快照立即用新语言集重跑。

每个审查服务器一次只允许一个 CallDiff 执行。同一快照的请求共享进行中的 promise。成功结果保存在有界会话缓存中，重复失败有 30 秒冷却，每次提交的 diff/base/PR/范围/空白变更都会取消先前快照的工作。服务器关闭和禁用功能也会取消所有 worker。

## UI 契约

禁用时，不出现调用流行、Dock、Lens、运行时预检、安装或分析请求。能力声明可包含静态当前审查 `consentPlan`（语言标签和仓库自有足迹估算），它从补丁路径计算，不探测 Node 或运行时。这与启用声明的 `installPlan` 不同，后者仅包含受管理存储中实际缺失的目标。

启用时，即使活动审查模式或运行时不可用，导航行仍可见。它在自动设置期间显示安静进度省略号，失败后显示不显眼的注意标记；打开它显示分阶段进度或显式恢复操作。在支持的快照上，客户端启动一个后台请求，并在 Dock 和所有虚拟化文件头之间共享结果。

当仅安装了部分变更语言时，响应仍成功并包含 `skippedLanguages`。Dock 在其自动安装运行时说明跳过文件数、语言和合并安装大小；每个跳过文件的 Lens 显示 `flow —`。完成会刷新声明并在会话内重试分析。紧凑的语言披露显示每个支持族的已安装状态、实测每包大小和累计估算已安装大小，同时保留手动提前安装控件。

Dock 的主要界面展示结果，而非引擎。它报告唯一变更步骤和受影响文件计数，然后提供两个专用视图：

- **Paths** 渲染可折叠的推断入口树，带源码位置和导航。
- **Raw** 在可复制的等宽界面中渲染 CallDiff 自身的规范、无色 ASCII 输出（带位置）。

提供方/版本和语法分析限定位于安静的信息提示之后。它们故意不出现在主标题中。原始视图不使用 `@pierre/diffs`：Pierre 将文本补丁建模为文件、块和行范围，而调用 diff 是对齐的父/子树。适配它需要假文件和块坐标，并会模糊树父子关系。专用 `<pre>` 保留 CallDiff 的精确人类输出和复制保真度；代价是原始行不能导航到源码，因此结构化 Paths 视图仍是交互视图。原始载荷限制为 1 MB，超出则拒绝而非静默截断。

Lens 使用同一共享结果，并选择包含当前文件（或其重命名源）中至少一个变更节点的完整推断入口树。它仅在入口树边界过滤，从不从选定树中裁剪节点，因此父级、未变更上下文、兄弟变更和后代保持可见。当前文件中的变更节点获得安静的焦点处理；任何有位置的节点都可导航到源码。带源码行的变更节点还暴露原生代码审查 Comment 操作。它就地打开现有注释工具栏，并创建与 diff、侧边栏、反馈导出和托管审查提交相同的行范围 `CodeAnnotation`。未变更上下文仅用于导航，因为它不是有效的旧/新内联 diff 目标。`flow N` 计数仍是该文件的唯一变更步骤计数。

代码审查在 Guide、外观和审查设置之后、Edit Mode 之前包含一次性、版本化的分析欢迎。它并排展示 **语义变更** 和 **调用流**。两个开关写入与设置 → 分析相同的 `reviewAnalysis` 设置，对话框参与现有的无栈链。调用流的开关文案即安装同意，使用服务器编写的当前审查标签和大小总量。

## 有意非目标

此实现不添加 CallDiff `reach` 查询、任意入口选择、内联 `@pierre/diffs` 装饰、持久化分析、自动 Ask AI 上下文、置信度/严重性评分或树搜索。这些可在快照和运行时契约证明可靠后评估。

## 验证要求

对此集成的更改必须保留：

- Bun/Pi 端点对等和 Pi vendoring；
- 精确受管理依赖固定和离线分析；
- 选择性变更语言预检、成功的部分结果和显式跳过文件状态；
- 裁剪后运行时加载预构建和本地编译的原生语法；
- 快照创建期间源仓库不可变性；
- 视图变更时拒绝过期结果并取消；
- 独立的语义变更和调用流设置；
- 一个共享结果驱动 Dock 和 Lens；
- 规范原始输出在 worker 边界有界，绝不从 UI 树重建；
- 每个相关文件 Lens 中完整、未裁剪的入口树；
- 来自变更、有源码位置的 Dock 和 Lens 行的原生行注释，未变更上下文被拒绝为内联注释目标；
- 版本化分析欢迎保留在无栈对话框链中；
- 每个审查会话每个目标一次自动尝试，无渲染驱动的失败重试循环，覆盖运行时无自动安装；
- 围绕验证和原子核心/包发布的跨进程安装串行化；
- 同意文案使用服务器编写的当前审查语言足迹和大小估算；
- 显式不支持/不可用 UI，而不是启用功能消失。
